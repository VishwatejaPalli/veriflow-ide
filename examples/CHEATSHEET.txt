=========================================

COMMAND-LINE EQUIVALENTS
------------------------
Simulation:
  iverilog -g2012 -o out.vvp design.sv tb.sv
  vvp out.vvp
  gtkwave waveform.vcd

Synthesis:
  yosys -s synth_script.ys
  yosys -p "read_verilog design.v; synth; write_verilog out.v"

Linting:
  verilator --lint-only -Wall design.sv
  verible-verilog-lint design.sv
  verible-verilog-lint --rules=rule1,rule2 design.sv

Formatting:
  verible-verilog-format --inplace design.sv
  verible-verilog-format --column_limit=100 design.sv

Layout:
  magic -dnull -noconsole script.tcl
  klayout layout.gds
  klayout -b -r drc_rules.drc layout.gds

Verification:
  netgen -batch lvs schem.sp layout.sp setup.tcl
  sta timing_script.tcl

Analog:
  ngspice -b netlist.sp -o output.log
  ngspice netlist.sp  # Interactive

COMMON FILE EXTENSIONS
----------------------
HDL Design:
  .v    → Verilog
  .sv   → SystemVerilog
  .vh   → Verilog header
  .svh  → SystemVerilog header

Simulation:
  .vvp  → VVP executable
  .vcd  → Value change dump (waveform)
  .fst  → Fast signal database

Synthesis:
  .ys   → Yosys script
  .json → JSON netlist
  .blif → Berkeley Logic Interchange Format

Layout:
  .gds  → GDSII stream
  .oas  → OASIS layout
  .mag  → Magic layout
  .def  → Design Exchange Format
  .lef  → Library Exchange Format

Analog:
  .sp   → SPICE netlist
  .cir  → Circuit netlist
  .lib  → Liberty timing library
  .sdc  → Synopsys Design Constraints

Scripts:
  .tcl  → Tool Command Language
  .drc  → DRC rules
  .lvs  → LVS rules

TIPS & TRICKS
-------------
1. Use Command Preview
   - Always check the command before running
   - Copy it for use in scripts

2. Check Diagnostics Tab
   - Click errors to jump to source
   - Filter by type (error/warning)

3. Use History Tab
   - Re-run previous commands
   - Track what you've executed

4. Organize Files
   - Use project hierarchy
   - Keep sources and tests separate

5. Start with Examples
   - Run make sim in demo_alu/
   - Modify and experiment

6. Check Tool Output
   - Read Console for detailed messages
   - Scroll for full context

7. Save Configurations
   - Copy successful commands
   - Create shell scripts or Makefiles

8. Use Waivers for Linting
   - Suppress false positives
   - Document why rules are waived


TROUBLESHOOTING
---------------
Tool not found:
  → Check: which tool_name
  → Install: sudo apt install tool_name
  → Path: echo $PATH

File not found:
  → Use absolute paths
  → Check current directory
  → Verify file exists

Permission denied:
  → chmod +x filename
  → Check file ownership
  → Run with proper permissions

Compilation errors:
  → Check syntax with linter first
  → Verify all modules defined
  → Check include paths

No waveform:
  → Ensure $dumpfile in testbench
  → Check simulation completed
  → Verify .vcd file created

Synthesis fails:
  → Lint with Verilator
  → Check unsupported constructs
  → Verify parameter values
